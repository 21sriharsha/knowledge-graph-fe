# X01 — BFF and API client

Status: draft · Wave: W0 · ADRs: 0002, 0007

## Summary
All backend access goes through Next.js server code. A typed client generated from
`apim/api-spec.yaml` calls Spring, attaches auth and correlation headers, and turns `ApiError`
responses into typed results the UI can render consistently.

## Personas and access
Infrastructure for every persona. Public endpoints are called without a token; `/api/studio/**`
calls carry the Supabase access token from the session cookie.

## Functional requirements
- X01-FR-1 `lib/api/schema.ts` is generated by openapi-typescript from
  `../knowledge-graph-be/apim/api-spec.yaml` (`pnpm api:types`); committed; CI fails on drift.
- X01-FR-2 `lib/api/server.ts` creates an openapi-fetch client per request with base URL `API_BASE_URL`
  (server-only env var). Importing it from a client component fails the build (`server-only`).
- X01-FR-3 Studio calls attach `Authorization: Bearer <access_token>` obtained from `@supabase/ssr`.
  If no session exists the call is not made and the caller receives `{ kind: "unauthenticated" }`.
- X01-FR-4 Every call sends `X-Request-Id` (incoming request's id, or a new UUID) and `traceparent`.
  The backend echoes `X-Request-Id`; it is attached to logs and to error results.
- X01-FR-5 Result type: `{ ok: true, data } | { ok: false, status, code, message, requestId, violations }`.
  Mapping: 401 → `unauthenticated`, 403 → `forbidden`, 404 → `not_found`, 409 → `conflict`,
  400 → `validation` (with `violations` keyed by field), 5xx/network/timeout → `unavailable`.
- X01-FR-6 Timeouts: 5 s for reader calls, 10 s for studio mutations; one retry with jitter for
  idempotent GETs on network error or 502/503/504; never retry POST/PUT/DELETE automatically.
- X01-FR-7 Route handlers under `app/api/bff/**` expose only what browser code needs (studio, search
  suggest, graph explorer, link previews, view counter). They validate input with zod, call the
  typed client, and return the result type as JSON with the matching HTTP status.
- X01-FR-8 Route handlers pass through only safe response headers; they never forward the
  `Authorization` header from the browser (there is none) or any backend host information.
- X01-FR-9 `POST /api/articles/{slug}/view` is fired through `app/api/bff/views/[slug]` with
  `keepalive`; failures are logged at DEBUG and ignored.
- X01-FR-10 Search `size` must always be sent explicitly (the spec's default is `0`).

## API contract
All operations listed in `apim/api-spec.yaml`. Feature specs name the calls they use.

## Observability
- Span per backend call: `http.client` with method, route template (`/api/articles/{slug}`), status,
  duration, `request_id`. No query strings containing user input in span names.
- Log at WARN for 4xx other than 401/404 on studio calls, ERROR for 5xx/timeouts, with `requestId`.
- Metric: backend call latency histogram and error count by route template and status class.

## Performance budget
- BFF overhead < 20 ms p95 over the raw backend call (same region).

## Acceptance criteria
- X01-AC-1 Given the spec changes and types are not regenerated, when CI runs, then the drift check fails.
- X01-AC-2 Given a browser bundle, when inspected, then it contains no backend base URL and no import
  of `lib/api/server.ts`.
- X01-AC-3 Given a backend 409 `DOMAIN_RULE_VIOLATION`, when a studio mutation calls the BFF, then the
  UI receives `{ ok:false, kind:"conflict", message, requestId }`.
- X01-AC-4 Given a backend 400 with `violations`, then each violation maps to its form field.
- X01-AC-5 Given a 503 on a GET, then it is retried once; given a 503 on a POST, then it is not retried.
- X01-AC-6 Given any backend call, then the outgoing request carries `X-Request-Id` and `traceparent`
  and the log line contains the same `requestId`.

## Out of scope
Business logic in route handlers; caching (see X04).

## Open questions / backend gaps
- The spec declares only success responses; error shapes come from `GlobalExceptionHandler`. Ask the
  backend to document `ApiError` responses in the spec (BG-9).
